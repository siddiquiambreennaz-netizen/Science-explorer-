# SCIENCE EXPLORER

An existing TanStack Start + React learning app with an AI Tutor, Scan & Learn, Chemistry/Physics activities, ready-made interactive games, and a topic-to-game creator.

## Local setup (Windows PowerShell)

1. Extract the ZIP.
2. Open PowerShell inside the folder containing `package.json`.
3. Install dependencies and set up server-side keys:

```powershell
npm install
Copy-Item .env.example .env
notepad .env
```

If `.env` already exists, keep it and edit it rather than overwriting it. Add your actual `GEMINI_API_KEY` and `ELEVENLABS_API_KEY` values. Do not put secrets in a `VITE_` variable or share `.env`.

4. Start the app:

```powershell
npm run dev
```

5. Open the local URL printed in the terminal. In **AI Tutor → AI Overview**, use **Test live AI response** to verify Gemini. Test ElevenLabs voice separately; a valid Gemini key does not validate an ElevenLabs key.

## AI game creator

From **Science Games**, choose **Create a game from your topic**. Enter a school topic, choose a grade (Classes 5–10; Class 9 is the default and Class 10 is Matric), and submit. Gemini generates the story, mission, interactive cards and target zones, hints, feedback, reward and a short end quiz. The game engine executes validated data; it does not execute code generated by the AI. If the API is not configured, the UI reports the error rather than fabricating a successful result.

The Solar System activity uses smiling CSS-drawn planet characters and asks the learner to drag or tap them into Planet 1–8 orbital positions. Game pages also have an optional 20-minute focus timer.

## Current Gemini model IDs

The project defaults to `gemini-3.5-flash-lite` and falls back to `gemini-3.8-flash`. Model access, rate limits and key permissions depend on the Google AI Studio project. The live connection test is the source of truth for the user's configured key.

## Available scripts

- `npm run dev` — local development server
- `npm run build` — production build
- `npm run test` — automated tests
- `npm run lint` — lint source files

## Security note

`.env.example` is a sample only. The actual keys belong in `.env` or your deployment's server-side secret configuration. Never commit, upload or send the real `.env` file.
